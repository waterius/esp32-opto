# Прошивка esp32-opto — дизайн

Дата: 2026-09-17. Статус: согласован по секциям, ждёт просмотра спеки.

## 1. Цель и рамки

Устройство постоянно подключено к питанию и к роутеру. Оно читает счётчик
**НАРТИС-100.121R** через оптопорт, по расписанию отправляет показания в облако
Waterius и даёт удалённый прозрачный доступ к оптопорту по RFC 2217. Веб-морда
доступна всегда.

Проект не для production: там, где можно упростить, упрощаем. Свои реализации
заменяем внешними библиотеками.

## 2. Цели сборки

PlatformIO, `framework = arduino`, `platform = espressif32@6.12.0`
(arduino-esp32 2.0.17), `board_build.filesystem = littlefs`.

| env | Плата | Разделы | Приложение | Оптопорт RX / TX | Особенности |
|---|---|---|---|---|---|
| `esp32-s3` | esp32-s3-devkitc-1 | `default_8MB.csv` | 3.19 МБ, 2 слота OTA | GPIO17 / GPIO18 | — |
| `esp32-c3` | esp32-c3-devkitm-1 | `min_spiffs.csv` | 1.875 МБ, 2 слота OTA, 128 КБ LittleFS | GPIO4 / GPIO5 | `-DARDUINO_USB_MODE=1` |

OTA обязателен на обеих платах. Картинок во фронтенде нет.

### Поток управления

Весь наш код работает в `loop()`. Свои задачи FreeRTOS создают только
библиотеки: `async_tcp` у AsyncTCP и задача сервера igrr. Мьютексов в нашем
коде нет.

**Правило для веб-хендлеров и колбэков RFC 2217:** они только ставят флаги и
читают снимок состояния. Блокирующий TLS, запись в NVS и работа с оптопортом
выполняются в `loop()`. Причина: колбэки Async исполняются в задаче
`async_tcp`, и долгие операции в них приводят к таймаутам и WDT.

### Автомат опроса в `loop()`

| Состояние | Действие | Переход |
|---|---|---|
| `Idle` | ждёт: истёк период, нажата кнопка или пора повторить после ошибки | `ReadMeter`, если опрос «в работе» и шина свободна; при выключенном опросе отправка идёт сразу в `SendCloud` |
| `ReadMeter` | берёт шину → выставляет порту параметры из настроек → `NartisMeter::read()` → отпускает шину | `SendCloud` для «отправить» и периода — в том числе после неудачного чтения; иначе `Idle` |
| `SendCloud` | `POST /api/source/iz/` с последними успешно прочитанными данными, если есть Wi-Fi, ключ и хотя бы одно успешное чтение | `Idle` |

- «Прочитать сейчас» — только чтение. При выключенном опросе кнопка недоступна.
- «Отправить сейчас» и срабатывание по периоду — чтение, если опрос «в работе»,
  затем отправка последних прочитанных данных. Отправка происходит, даже если
  чтение не удалось или опрос выключен.
- Ошибка чтения → повтор чтения через 5 минут, без отправки.
  Ошибка отправки → повтор отправки через 5 минут.

### Арбитраж шины

Владелец шины: `свободна` / `опрос` / `прозрачная сессия`.

1. Клиент подключился к TCP-порту RFC 2217 → шина сразу переходит к нему.
   Идущий опрос прерывается и до следующего цикла по периоду не повторяется.
   Прерывание не считается ошибкой: повтора чтения через 5 минут нет, а в
   облако, если это была отправка, уходят последние прочитанные данные.
2. Клиент закрыл TCP-соединение → шина свободна. Параметры порта не
   восстанавливаются: каждый опрос выставляет их сам при старте.

Прерывание блокирующего чтения: колбэк подключения взводит атомарный флаг
`preempt` в `opto_bus`. Адаптер проверяет его в цикле ожидания байтов и между
запросами и при взведённом флаге выходит сразу, без DISC.

Таймаута бездействия у прозрачной сессии нет. Забытое открытое соединение
останавливает отправку в облако, пока его не закроют.

## 4. Счётчик НАРТИС

| Параметр | Значение |
|---|---|
| Протокол | СПОДЭС = DLMS/COSEM поверх HDLC, библиотека GuruxDLMS.c |
| Порт | 9600 8N1, сразу, без режима E |
| Клиент | 32 (считыватель), аутентификация LLS |
| Сервер | logical 1, physical из настроек; 0 = перебор 16 → 17; адрес 2 байта |
| Пароль | из настроек, по умолчанию `111` (заводской пароль чтения НАРТИС-100) |

Читаемые OBIS:

| Что | OBIS | Класс, атрибут |
|---|---|---|
| Активная энергия, сумма | `1.0.1.8.0.255` | 3, атрибуты 2 и 3 (scaler/unit) |
| Тарифы T1…T4 | `1.0.1.8.1.255` … `1.0.1.8.4.255` | 3, атрибуты 2 и 3 |
| Серийный номер | `0.0.96.1.0.255` | 1, атрибут 2 |
| Тип счётчика | `0.0.96.1.1.255` | 1, атрибут 2 |
| Версия ПО | `0.0.96.1.2.255` | 1, атрибут 2 |
| Дата и время | `0.0.1.0.0.255` | 8, атрибут 2 |

Значение приводится к кВт·ч: умножается на 10^scaler, при единице Вт·ч (код 30)
делится на 1000. Тарифы читаются по порядку до первого отказа.

**Счётчик отверг пароль → опрос выключается.** Тумблер «в работе» сбрасывается
и сохраняется в NVS, причина видна на странице статуса. Включить опрос обратно
может только пользователь этим тумблером. После 5 неверных паролей счётчик
блокирует интерфейсы на сутки, а повтор раз в 5 минут дошёл бы до блокировки
за 25 минут. Перебор адресов попыток не расходует: на чужой адрес счётчик не
отвечает на SNRM, и до пароля дело не доходит.

## 5. Облако Waterius

- `POST {host}/api/source/iz/`, JSON, заголовки `Waterius-Token` и
  `Waterius-Email`. HTTPS без проверки сертификата, как в прошивке Waterius.
  Успех — только HTTP 200.
- Поля: `key`, `email`, `sn`, `total`, `data_type=2`, `total1..4`,
  `data_type1..4` (5 день, 6 ночь, 7 пик, 8 полупик), `fw`, `model`,
  `meter_fw`, `meter_time`, `chip_id`, `ip`, `rssi`.
- `meter_fw` и `meter_time` бэкенд сейчас не сохраняет: их нет в
  `IZSerializer`, лишние поля он игнорирует.
- Отправляются последние успешно прочитанные данные, даже если опрос выключен
  или последнее чтение не удалось. Дополнительное поле `meter_read_at` — когда
  они прочитаны (по NTP, ISO 8601; пусто, если времени нет). Если успешного
  чтения не было ни разу, отправка пропускается.
- Поле `ota_error` — код ошибки последнего OTA через сервер (раздел 8).
- Из ответа сервера разбирается только блок `ota` (раздел 8). Остальные
  настройки из ответа не применяются.

## 6. Веб

Фронтенд на LittleFS: `index.html`, `settings.html`, `wifi.html`, `app.js`,
`style.css`. Страницы статические, данные только через JSON API, шаблонизатор
`%var%` не используется. У всех страниц общая шапка со ссылками на три страницы
и на `/update`. Авторизации нет. Пароли отдаются в `GET`-ответах открытым
текстом.

### `/` — статус, только чтение

| Блок | Поля |
|---|---|
| Счётчик | серийный номер, модель, версия ПО, время счётчика |
| Показания | всего кВт·ч, T1…T4 |
| Последнее чтение | время, «ок» или текст ошибки; «опрос выключен» и причина |
| Облако | время последней отправки, HTTP-код, через сколько следующая |
| Устройство | версия прошивки, IP, RSSI, аптайм, свободная память, режим Wi-Fi |

Кнопки: «Прочитать сейчас», «Отправить сейчас», «Перезагрузить».
API: `GET /api/status` (страница опрашивает сама), `POST /api/read`,
`POST /api/send`, `POST /api/reboot`.

### `/settings`

| Группа | Параметры, умолчание |
|---|---|
| Оптопорт | скорость 9600; биты 8; чётность N/E/O, N; стоп-биты 1/2, 1 |
| Счётчик | в работе, да; адрес 0 (авто); пароль LLS `111` |
| Облако | период, мин, 60; сервер `https://cloud.waterius.ru`; ключ; e-mail |
| Прозрачный serial | включён, да; TCP-порт 2217 |

API: `GET /api/settings`, `POST /api/settings`.

### `/wifi`

| Блок | Поля |
|---|---|
| Сети | SSID, уровень 1…4, канал, защита; клик подставляет SSID |
| Подключение | SSID, пароль |
| Состояние | текущая сеть, IP, RSSI, режим STA / AP+STA |

API: `GET /api/networks`, `POST /api/wifi`, `GET /api/wifi_status`.

Из портала waterius (`waterius/ESP8266/src/portal/`) переносится: фоновый скан
и формат ответа `ssid`, `level`, `wifi_channel`, `bssid`; быстрый коннект по
BSSID и каналу; опрос статуса подключения; captive portal — `DNSServer` с
перехватом `*` на `192.168.4.1` и обработчики `/generate_204`,
`/hotspot-detect.html`, `/ncsi.txt`, `/connecttest.txt`, `/canonical.html`,
`/success.txt`, `/redirect`, `/wpad.dat`, `/fwlink`. При переносе на ESP32:
`ESPAsyncTCP` → `AsyncTCP`, `getParam()` возвращает `const AsyncWebParameter*`,
`.setFilter()` ставится последним в цепочке.

## 7. Wi-Fi

| Ситуация | Поведение |
|---|---|
| Сеть не сохранена | только AP `esp32-opto-XXXX` (XXXX — последние байты chip id), без пароля, captive portal, адрес `192.168.4.1` |
| Сеть сохранена | STA, `WiFi.setSleep(false)` |
| Нет связи с роутером 2 минуты | AP+STA: точка доступа с captive portal поднята, STA переподключается раз в 60 секунд |
| STA подключилась, к AP никто не подключён | AP гасится |

mDNS нет. В режиме STA адрес устройства смотрится в роутере или в USB-логе.

## 8. OTA

Три пути обновления, все ставят прошивку и образ LittleFS отдельно.
Автоматического отката при падении новой прошивки нет.

- **ElegantOTA** в Async-режиме (`-DELEGANTOTA_USE_ASYNC_WEBSERVER=1`),
  страница `/update`: загрузка прошивки и образа LittleFS вручную.
- **ArduinoOTA** из ядра — для `pio run -t upload --upload-port <IP>`.
- **Через сервер Waterius** — как в прошивке waterius (`ESP8266/src/ota_update.cpp`,
  `ota_parse.h`), описано ниже.

### OTA через сервер Waterius

**Запуск.** Решает сервер: он сравнивает присланное устройством поле `fw` с
целевой версией и, если нужно обновление, добавляет в ответ на
`POST /api/source/iz/` блок:

```json
{"ota": {"firmware":   {"url": "...", "md5": "...", "size": 0},
         "filesystem": {"url": "...", "md5": "...", "size": 0}}}
```

Любая секция может отсутствовать; `url` и `md5` обязательны, `size` не
проверяется. Устройство версии не сравнивает. Из ответа сервера разбирается
только ключ `ota`, остальное игнорируется.

**Выполнение** — в `loop()`, сразу после успешной отправки в `SendCloud`:

1. Если открыта прозрачная сессия — обновление пропускается. Сервер пришлёт
   блок снова в следующем ответе.
2. Сначала образ ФС (`U_SPIFFS`), затем прошивка (`U_FLASH`). Перезагрузки
   между ними нет.
3. Загрузчик свой: `HTTPClient` + `WiFiClientSecure` с `setInsecure()` →
   `Update.begin(размер, тип)` → `Update.setMD5(md5)` → `Update.writeStream()` →
   `Update.end()`. Готовый `HTTPUpdate` ядра не подходит: в arduino-esp32
   2.0.17 у него нет `setMD5sum`, md5 он берёт только из заголовка `x-MD5`,
   которого сервер Waterius не отдаёт.
4. Успех → `ESP.restart()`. Об успехе устройство отдельно не сообщает: сервер
   увидит новую версию в поле `fw`.

**Ошибки.** Код сохраняется в NVS и уходит серверу полем `ota_error` в
следующем запросе, после успешной отправки обнуляется. Повторов на устройстве
нет, их организует сервер (`max_retries` на его стороне).

| `ota_error` | Значение |
|---|---|
| 0 | нет ошибки |
| 1 | не разобран блок `ota` |
| 2 | ошибка обновления ФС |
| 3 | ошибка обновления прошивки |

Код 4 из waterius (низкое напряжение батареи) не используется: питание
постоянное.

**Версия прошивки** задаётся в `platformio.ini` и передаётся флагом
`-DFIRMWARE_VERSION`, как в waterius; в запросе это поле `fw`.

**Разделы.** ФС обновляется в раздел с subtype `spiffs` — он есть в
`min_spiffs.csv` и `default_8MB.csv`. Настройки лежат в NVS, поэтому
обновление ФС их не стирает.

**Зависимость от бэкенда.** Сейчас `IZServer` (`waterius.site.back`,
`apps/source/views_iz.py`) всегда отвечает пустым телом и `ota_error` не
принимает. Выдачу блока `ota` для `/api/source/iz/` владелец добавит в облако
отдельно; прошивка к этому готова заранее.

## 9. Настройки

- Хранятся только в NVS. LittleFS не подходит: обновление образа файловой
  системы стирает раздел целиком.
- Одна структура `Settings` и номер версии формата. Версия не совпала →
  умолчания, без миграции.
- Хендлеры кладут новые значения в буфер и ставят флаг, в NVS пишет `loop()`.
- Последнее успешное чтение (`MeterData` и время чтения) — отдельная запись в
  NVS, пишется после каждого успешного чтения. Так данные для облака
  переживают перезагрузку.
- Удержание BOOT 5 секунд — сброс к умолчаниям (GPIO0 на S3, GPIO9 на C3).

Поля `Settings`: `ssid`, `pass`, `bssid`, `channel`; `serial` (baud, bits,
parity, stop); `meterEnabled`, `meterAddr`, `meterPwd`; `periodMin`, `host`, `key`, `email`;
`rfcEnabled`, `rfcPort`.

## 10. Прозрачный serial

- Сервер igrr/rfc2217-server (Apache-2.0), копия в `lib/rfc2217-server/` со
  своим `library.json`.
- Патч: у библиотеки нет колбэков на SET_DATASIZE / SET_PARITY / SET_STOPSIZE,
  она только подтверждает их клиенту. Добавляем колбэки и применяем
  параметры к UART.
- Колбэк подключения клиента → `preempt` и передача шины (раздел 3).
- Проверка с ПК: `python -m serial.tools.miniterm rfc2217://<IP>:2217 9600`.

## 12. Проверка

- После каждого шага собираются оба env; результат — по коду возврата `pio`.
- Юнит-тестов нет. Проверка на железе по порядку: AP и captive portal →
  подключение к роутеру → три страницы → чтение счётчика → облако отвечает
  200 → клиент RFC 2217 прерывает опрос → OTA прошивки и LittleFS через
  `/update`.
- OTA через сервер Waterius проверяется до поддержки в бэкенде: в поле «сервер»
  указывается локальный HTTP-сервер, который отвечает на `/api/source/iz/`
  блоком `ota` и раздаёт бинарники.

## 13. Лицензии

Пока прошивка не распространяется, лицензии ни на что не влияют. При установке
в устройства Waterius связка Gurux (GPLv2) и ElegantOTA (AGPLv3) в одном
бинаре может оказаться несовместимой, а закрытая прошивка с Gurux требует
коммерческой лицензии Gurux. Замена ElegantOTA в этом случае — свой `/update`
поверх `Update.h`.

## 14. Вне рамок

- **Прозрачный serial через удалённый сервер.** В бэкенде Waterius канала для
  этого нет; это отдельный подпроект со своей спекой.
- Режим E IEC 62056-21 и переключение скорости.
- Запись в счётчик, синхронизация его времени.
- Применение настроек из ответа облака (кроме блока `ota`).
- Поддержка OTA и `ota_error` в `IZServer` бэкенда Waterius — делает владелец
  облака отдельно.
- mDNS, авторизация на страницах, таймаут прозрачной сессии, автооткат OTA,
  юнит-тесты.
