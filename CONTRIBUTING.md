# Как участвовать

Спасибо за интерес. Проект маленький и не production: здесь ценится простота
и то, что можно проверить без паяльника.

**Язык проекта — русский**: документация, комментарии в коде, сообщения
коммитов, описания задач и пулл-реквестов.

## Сборка и проверка

PlatformIO Core лежит в `~/.platformio/penv/bin/pio` и в PATH не добавлен,
поэтому вызывается по полному пути.

```sh
~/.platformio/penv/bin/pio run -e esp32-s3 -e esp32-c3   # сборка обеих плат
~/.platformio/penv/bin/pio test -e native                # юнит-тесты, без платы
~/.platformio/penv/bin/pio check -e esp32-c3             # cppcheck
python3 tools/fake_device.py                             # страницы и API без платы
python3 tools/fake_cloud.py                              # заглушка облака
```

Перед пулл-реквестом должны быть зелёными **все три**: сборка обеих плат,
тесты и статический анализ. Код возврата смотреть у самого `pio`: если после
него в конвейере стоит `grep` или `tail`, код будет от них.

Находок у `pio check` сейчас нет ни в одном окружении, и так это и держится.
Ложное срабатывание глушится построчным `// cppcheck-suppress <id>` с
объяснением рядом, а не поднятием порога и не правкой кода под линтер.

## Правила, которые легко нарушить не заметив

**Решения — в ядре, исполнение — в порту.** Когда переподключаться, когда
поднимать точку доступа, когда перезагружаться, когда закрывать прозрачную
сессию — это автоматы в `src/core/`, которые не зовут ни одной функции Arduino
и проверяются тестами на компьютере. `src/port/` только сообщает им факты и
исполняет действия. Новую логику восстановления добавлять так же, иначе её
нельзя будет проверить без платы.

**Ядро не включает заголовки Arduino.** Время оно берёт через `core::nowMs()` /
`core::sleepMs()`, порт — через `core::IOptoPort`.

**Новый модуль ядра надо добавить в `build_src_filter`** окружения `native` в
`platformio.ini`, иначе тесты его не увидят.

**Весь наш код работает в `loop()`.** Веб-хендлеры и колбэки сервера RFC 2217
только читают `app` и ставят атомарные флаги; UART, NVS, TLS и переключения
Wi-Fi — только из `loop()`.

**Вывод — только через `Log`** (`src/port/log.h`), не `Serial`: иначе
сообщения нет на странице лога.

**Версия настроек.** Добавление и удаление поля в `core::Settings` версию
**не двигают** — новое поле берёт умолчание само. `SETTINGS_VERSION`
поднимается, только когда меняется **смысл** уже существующего поля, и тогда
на подъём пишется функция `upgradeNtoN+1()` и тест на неё.

## Документация

Каждое утверждение в `docs/` помечается уровнем достоверности: **[проверено]**
(со ссылкой в [docs/sources.md](docs/sources.md)), **[по схеме]**,
**[по фото]**, **[гипотеза]**, **[измерить]**. Новые документы нумеруются
дальше и добавляются в таблицу [docs/README.md](docs/README.md).

## Коммиты и пулл-реквесты

Conventional commits на русском: `feat: …`, `fix: …`, `docs: …`, `chore: …`.
В теле — зачем, а не что: «что» видно из диффа.

В пулл-реквесте опишите, что проверено и как. Если проверяли на плате —
напишите, на какой и с каким счётчиком.

## Об ошибках в счётчике

Осторожнее с паролем: **после пяти неверных попыток НАРТИС блокирует
интерфейсы на сутки.** Поэтому пароль берётся только из настроек, и никакого
перебора в коде быть не должно.
